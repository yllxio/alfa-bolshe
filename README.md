# Альфа.Больше — демонстрационный кредитный кабинет

> **Внимание:** учебный прототип для хакатона, **не** банковская система, оферта или сервис выдачи реальных кредитов. Используйте только вымышленные сведения.

## Что входит

- Веб-кабинет предпринимателя: бизнес-профиль, сценарии открытия и развития, цели, смета, прогноз, выбор и сравнение демонстрационных продуктов, заявка, отслеживание, документы и моделируемая выдача.
- Веб-кабинет сотрудника: очередь заявок, досье, модельный скоринг/DSCR, документы, запрос сведений, одобрение/отказ/альтернативные условия.
- Автономный сервер без платных интеграций: отдаёт сайт, предоставляет **только синтетический** поиск по двум демонстрационным ИНН и сохраняет заявки в SQLite для демонстрации работы в разных браузерах.
- Финансовая логика: аннуитет, потребность в финансировании, DSCR, предварительная сумма кредита и демонстрационные скоринговые факторы.

### Серьёзные ограничения

1. **ИИ в этом ZIP — сценарный помощник с заранее заданными правилами и формулами, а не настоящая LLM.** Он не отвечает на произвольные вопросы. Для использования настоящей LLM в рамках конкурса нужна локальная модель с открытыми весами; она в данную сборку не включена.
2. **Поиск настоящих компаний не работает.** API `/api/company` возвращает только специально вымышленные компании из файла `server.py`; запросы к ФНС/БКИ не отправляются.
3. Система для жюри — **синтетическая демоверсия, не enterprise-приложение**: нет пользовательской регистрации, настоящей банковской авторизации, обработки персональных данных, реальных подписей или движения денег. В интерфейсе роль меняется демонстрационным переключателем. API обмена заявками рассчитан на доверенную локальную демонстрационную среду и не предназначен для открытого интернета без защиты.
4. Финансовая и продуктовая информация, включая ставки и диапазоны, **демонстрационная**, не банковская рекомендация.
5. Файлы, добавленные через форму «Документы», в некоторых сценариях хранятся **только как название и размер**, а не как содержимое. Раздел паспорта может считывать текст локального файла отдельно; эти возможности нужно различать.
6. Синхронизация общих заявок работает по опросу и принципу «последняя запись», без защиты от одновременного изменения одной заявки двумя сотрудниками.
7. Сама подготовленная Docker-конфигурация **не проверялась в реальном Docker** в среде подготовки (движок Docker отсутствовал); проверены синтаксис и работа Python-сервера в доступной среде.

## Запуск через Docker (основной способ)

Установите Docker Desktop с Docker Compose (Windows: Docker Desktop с Linux containers / WSL2).

```bash
docker compose up --build -d
```

Откройте **http://localhost:8080**. Проверка API: http://localhost:8080/health.

Чтобы остановить контейнер:

```bash
docker compose down
```

Чтобы удалить **демонстрационную** базу заявок:

```bash
docker compose down -v
```

Данные заявок сохраняются в именованном volume `alfa_demo_data` и не теряются после обычного перезапуска контейнера.

### Альтернативный запуск без Docker

Требуется Python **3.12** (стандартная библиотека, без установки пакетов):

```bash
# macOS/Linux
ALFA_DB_PATH=./demo.sqlite python server.py
```

Для Windows PowerShell:

```powershell
$env:ALFA_DB_PATH = "./demo.sqlite"
python server.py
```

Откройте http://localhost:8080.

## Как пройти главный сквозной сценарий

1. На главной выберите **«Развивать бизнес»** или **«Открыть своё дело»**. Создайте **вымышленный** бизнес-профиль. При желании перейдите в «Мой бизнес», укажите демо-ИНН `0000000000` для ООО или `000000000000` для ИП и нажмите **«Найти в реестре»**; подтвердите распознанные поля. Можно работать и с ручным вводом.
2. Откройте **«Для вашего дела»** / «Цели», выберите цель, затем откройте **«Мои проекты»** для расчёта бюджета. Либо перейдите сразу в «Финансирование».
3. В **«Финансирование»** задайте сумму и срок, сравните демонстрационные аннуитетные продукты, выберите подходящий и нажмите оформление заявки.
4. Подтвердите учебные полномочия/согласие и отправьте **демонстрационную** заявку. В «Мои заявки» появятся её номер и история.
5. Нажмите **«Сотруднику банка»**. В очереди выберите новую заявку, откройте досье, **выполните синтетические проверки**, изучите вкладки «Финансы» и «Скоринг». При необходимости добавьте учебные документы и подтвердите полноту (в интерфейсе есть действия для демоданных).
6. Выберите решение **«Одобрить»**, **«Отказать»**, **«Запросить данные»** или **«Предложить другие условия»**. Одобрение зависит от демонстрационных проверок и DSCR; если оно заблокировано, посмотрите причины и пройдите альтернативную ветку.
7. Переключитесь обратно в кабинет предпринимателя. Откройте «Мои заявки»: статус и предложение отражают решение сотрудника. При одобрении перейдите к демонстрационному оформлению, подпишите условный документ и выполните симуляцию выдачи.
8. Для проверки связи между двумя компьютерами / браузерами откройте **тот же серверный адрес** в другом браузере и переключитесь в кабинет сотрудника. Новые/изменённые заявки подгружаются примерно раз в 3,5 секунды. В обоих браузерах используйте только синтетические данные.

> Важно: для проверки на **одном компьютере** достаточно переключаться между двумя кабинетами. Если браузеры расположены на разных компьютерах, порт Docker по умолчанию привязан к `127.0.0.1` по соображениям безопасности; необходимо отдельно настраивать локальную сеть и ограничение доступа. Не публикуйте эту демоверсию без авторизации в открытый интернет.

## Тестовые профили

| ИНН | Вымышленная компания | Основной сценарий |
| --- | --- | --- |
| `0000000000` | ООО «Тестовая кофейня» | Расширение действующего бизнеса |
| `000000000000` | ИП Тестовый Предприниматель | Дополнительное образование |

Все реквизиты, показатели и данные реестра **вымышлены**. Сайт может предлагать собственные демонстрационные начальные показатели до выбора компании.

## Состав проекта

- `index.html`, `style.css`, `app.js`, `redesign.js`, `product-rules.js`, `business-data.js`, `passport.js` — оригинальная веб-часть (в `index.html` добавено подключение синхронизации).
- `sync.js` — демонстрационная двусторонняя синхронизация заявок с сервером.
- `server.py` — веб-сервер и два API с синтетическими данными; SQLite.
- `vendor/` — локальная PDF.js (см. `THIRD_PARTY_NOTICES`).
- `compose.yaml`, `Dockerfile`, `.dockerignore`, `.env.example`, `requirements.lock`, `.gitignore` — воспроизводимый запуск.
- `openapi.yaml`, `docs/architecture.md`, `docs/state-machine.md`, `docs/data-model.md`, `docs/test-cases.md`, `docs/api-collection.json` — материалы для проверки.
- `tests/test_server.py` — серверные тесты без дополнительных зависимостей.
- `_export/` — исходный отчёт о копировании сайта.

## API

См. `openapi.yaml` и `docs/api-collection.json`:

- `GET /health` — проверка работоспособности сервера;
- `GET /api/company?inn=...` — поиск **только синтетических** компаний;
- `GET /api/applications` — демонстрационная очередь заявок;
- `POST /api/applications` — сохранить одну демонстрационную заявку.

OpenAPI/Swagger: спецификация `openapi.yaml` предназначена для просмотра в редакторе OpenAPI. В данной версии отдельный интерактивный Swagger UI не встроен.
